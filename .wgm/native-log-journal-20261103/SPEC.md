# Native diagnostic-log journal — approved first slice

## Goal and boundary
The operator approved crash-recoverable storage for native diagnostic logs (two explicit yes responses). Implement one real LinkLab slice based on reviewed `90c8b113c77dfa9240c0a1ccb9bce15e32f0724b`, then prove recovery before reuse elsewhere. Save editing, save/config checksums and other user-data contracts are unchanged. No AGENTS edits.

## Magic moment and smallest demo
An interrupted native-style export must not destroy the last committed diagnostics. Restart, recover the same transaction idempotently, export again, and retrieve the actual `.log` bytes through the existing Drop API. Host fault models and ARM compilation are explicitly separate from real SD/power-loss observations.

## Native contract
- libctru's libc rename may delete an existing destination before retrying. Do not use that as an atomic overwrite primitive.
- The new store is single-writer per app and confined to fixed diagnostic-log names, not an arbitrary save-file transaction API. No hostile concurrent filesystem writer or cryptographic-authentication guarantee is claimed.
- Fully prepare/validate/flush/close the new log before publishing an immutable checked intent record. Bind old/new lengths, data integrity checks, rotation/previous state, version and metadata checksum. Fixed-size/bounded encoding, no metadata-supplied paths, unknown flags/version/reserved fields reject.
- Retain the old committed generation before replacing its active name. Use exclusive/no-overwrite moves, never delete an existing destination to retry a move. Native backend uses real FSUSER_RenameFile semantics with explicit archive ownership, not the unsafe libc fallback. The host model must reject overwrite too.
- A pending record is never truncated/replaced by a new commit. Recover it first. Recovery follows only recognized content/state combinations; malformed metadata, unknown files, corruption, symlinks/FIFOs and oversized files fail visibly without discarding recoverable bytes.
- After intent publication, interruptions must leave either the old generation or a validated new generation recoverable. Rotation retains old active as `.previous`; nonrotation preserves the entire prior committed prefix in new active. Previous generation replacement is permitted only at the declared successful rotation boundary.
- Recovery is bounded and idempotent. Return success only for a fully checked stable state; incomplete cleanup/archive close is visibly pending, with ownership retained for retry/shutdown. Do not drop a resource handle because cleanup failed.
- Invalid pre-existing user-visible logs retain R1's fail-closed behavior; do not silently salvage/trim corrupt evidence. A valid legacy orphan `.tmp` with no active/journal must not be overwritten on upgrade.
- Reserved sidecars are documented and never end in `.log`; active remains `3ds/logs/3ds_linklab.log` so existing Drop discovery/pull still work. Raw backup/staging retrieval is documented for unresolved recovery. CRC/checksum integrity is not authentication.

## Concrete transaction design
- Derive fixed owned names from one active diagnostic `.log`: staged `.tmp`, intent `.txn`, old-active `.bak`, `.previous`, and previous backup. Do not read paths from metadata. Old/unknown sidecars without a valid matching intent cause visible refusal, not deletion. In particular, absent active plus a legacy orphan staged log must be retained on upgrade.
- Use one bounded immutable v1 intent (fixed64-byte little-endian record): magic/version/known flags, old/new/previous lengths and integrity checks, zero reserved fields, and a metadata checksum. Check encoding/size and read it back before any active-name move. No phase rewrite of that same record is needed; recognized file placements encode progress.
- Normal transition: fully prepared new file → publish checked intent → move old active to backup exclusively → on rotation move previous to its backup exclusively → move staged to now-absent active → verify active → on rotation move old active backup to now-absent previous → verify retained data → cleanup only known obsolete artifacts → remove intent last.
- Nonrotation must compare the complete old prefix against the prepared new log before any mutation; verify that retained prefix before discarding the old backup. Rotation keeps old active bytes exactly as previous. Unknown content/state combinations fail closed.
- Valid intent plus validated new data at staging or active permits bounded roll-forward through the recognized transitions. Corrupt/missing transaction data must retain recoverable generations and return a visible error; no best-effort truncation. Repeated recovery after success is a no-op. Cleanup errors retain intent/ownership for retry.
- Native exclusive move uses direct FSUSER_RenameFile on the same SDMC archive, never the libc overwrite adapter. Explicit archive acquisition/close/retry/shutdown ownership is tested; failed close cannot lose its handle or open unlimited replacements. Host exclusive move must also reject an existing destination, not rely on a racy existence check.
- CRC/checksum checks detect accidental corruption, not hostile authentication. The fixed namespace and single-writer assumption remain explicit. Models may simulate exact SDK failures but cannot claim real media durability.

## Application integration
Native builds use the new store for recovery before touching staging, then commit the prepared log through the journal. Ordinary host behavior and its eight existing assertions remain unchanged. A clearly labeled host-native model build exercises the same production integration. Native SD root handling must not mkdir a device mount as a normal directory. Expose pending/recovered/failure states honestly in the native UI and retry/shutdown path. No automatic uploads or physical-test claims.

## Executable acceptance matrix (normative)
Definitions: a generation is an exact committed log byte string; intent is the checked immutable transaction record; R5 is this slice, R1 is the reviewed corruption fix. This R5 plan governs only its slice, not the unfinished root app T1/T2. Its new tests are additive to the existing matrix gate, never replacements.

Exact names for active `3ds_linklab.log`: stage `3ds_linklab.log.tmp`, intent `3ds_linklab.log.txn`, active backup `3ds_linklab.log.bak`, previous `3ds_linklab.previous`, previous backup `3ds_linklab.previous.bak`. None of the sidecars end in `.log`.

Intent v1 is exactly64 bytes, little-endian: magic8 bytes `NLOGTX1` plus NUL; version at8=1; flags at12 (old-present1, rotation2, previous-present4; no unknown bits); old length/CRC32 at16/20; new length/CRC32 at24/28; previous length/CRC32 at32/36; reserved40..59 zero; CRC32 of bytes0..59 at60. Lengths are bounded to256KiB. Publish with exclusive creation, full write/flush/close and readback verification before namespace moves. A partial/corrupt intent is refused with data retained, not silently deleted. This v1 layout is normative for the first slice; a later format change requires an explicit new version and matching tests/spec.

Test drivers are new implementation deliverables; absence is a failed signal, not a skipped test. `make native-storage-model` builds the production C store/logger with a clearly labeled HOST NATIVE MODEL driver, not a hardware claim. Its `describe-stages` mode must expose the actual checkpoint registry; tests independently require every logical stage below to occur in an applicable fixture.

Logical stages: scan_old, scan_new, scan_previous, verify_prefix, intent_open, intent_write, intent_flush, intent_close, intent_verify, backup_active, backup_previous, publish_active, verify_active, publish_previous, verify_previous, remove_old_backup, remove_previous_backup, remove_intent. Driver selectors `before:<stage>`/`after:<stage>` terminate at that production checkpoint (exit86); `error:<stage>` returns EIO through that operation. Recovery uses the same checkpoints and a fixed maximum32 transitions per call. Each child process has a five-second test deadline; no infinite retry loop.
